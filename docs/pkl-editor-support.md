# What the editor offers

What pkl-lsp answers on `/edit` about code written against `@fh-dashboard`: completion, hover,
go-to-definition and errors flagged before the build. Use it when shaping the library: a shape
the editor follows is one an author can discover without the docs, and a gap is a cost the shape
has to be worth.

`PklEditorSupportSuite` asks each case below, at the cursor `‸`, through `LspBridge.session`
as the page's `@codemirror/lsp-client` connects, in a workspace the backend has prepared
(bootstrapped, a dump seeded, built once). It renders this table. A gap that starts working
fails the suite too, so the table cannot lag in either direction. Each case's source also goes
through the dashboard build, so no case asks about code the build refuses.

pkl-lsp resolves `@fh-dashboard` and `@fh-home` only through a project it has loaded. It loads
one from `<workspace>/.pkl-lsp/projects.json`, and only for a client that declares the workspace
folder. A desktop editor gets that file by syncing, which runs a `pkl` CLI.
